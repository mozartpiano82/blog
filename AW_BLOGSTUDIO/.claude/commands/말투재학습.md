## 이 명령이 따로 있는 까닭

전에는 화면의 「말투를 다시 배울까요?」 가 `/정리` 를 불렀다.
그런데 `/정리` 는 **새로 넣어주신 자료를 분류하는** 명령이다.
넣으신 게 없으면 할 일이 없고, 넣으셨으면 엉뚱하게 그것만 본다.

**화면이 약속한 것과 실제로 하는 일이 달랐다.**
원장님은 "고쳐준 걸 다시 배운다" 고 들으셨는데 프로그램은 딴 일을 했다.

여기서는 **이미 있는 것**만 본다. 새 자료는 안 건드린다.

## 할 일

### ① 먼저 볼 것이 있는지 센다

```bash
node bin/lib/checker.mjs history --전부
ls 20_완성글/*/편집본.md 2>/dev/null | wc -l
```

**편집본이 2편 미만이면 여기서 멈춘다.** 이렇게 말씀드린다.

```
아직 고쳐주신 글이 N편이라 다시 배울 게 별로 없어요.
두 편만 더 알려주시면 그때 제대로 배워드릴게요.
```

한 편으로 배우면 **그 글에서만 그러셨던 것**을 습관으로 굳힌다.
그건 배우는 게 아니라 잘못 외우는 것이다.

### ② 무엇이 달라졌는지 다시 센다

편집본이 있는 글마다 돌린다. 이미 센 것도 다시 센다 —
그 사이에 표현사전이 바뀌었을 수 있다.

```bash
node bin/lib/checker.mjs feedback 20_완성글/<폴더>/최종.md 20_완성글/<폴더>/편집본.md
```

이 명령이 **알아서** 한다:
- 편집률을 재서 `_발행대장.json` 에 적는다
- 되풀이되는 손질을 `10_학원위키/톤가이드.md` §편집으로 배운 것 에 적는다
- 표현사전을 갱신하고, 판정이 바뀐 것만 여쭐 목록으로 돌려준다
- 다시 안 나올 표현은 잊는다

**같은 계산을 여기서 따로 하지 않는다.** 화면에서 하시든 채팅에서 하시든
저 명령 하나를 지나야 한다. 두 곳이 각자 세면 두 곳이 엇갈린다.

### ③ 톤가이드 목표치를 다시 잰다

원장님이 고치신 **편집본들**로 다시 잰다. 처음 톤 분석은 원장님 옛 글로
잰 것이라, 이 프로그램 글을 고치시는 방식과는 다를 수 있다.

규격은 `.claude/지식층/톤입력-설계.md` §5 (기계 판독 블록).
**편집본이 4편 미만이면 목표치는 건드리지 않는다** — 표본이 모자라면
지금 것이 더 낫다.

### ④ 무엇이 달라졌는지 보여드린다

```
고쳐주신 글 6편을 다시 읽었어요.

  편집률   32% → 18% 로 내려왔어요. 원장님 글에 가까워지고 있어요.
  새로 배운 것
    · 긴 문장을 두세 개로 쪼개신다 (4편)
    · '거든요' 를 더 쓰신다 (3편)
  잊은 것
    · 한 번만 나오고 다시 안 나온 표현 23개

앞으로 쓰는 글에 이대로 반영돼요.
```

**전과 후를 나란히 말씀드린다.** "배웠어요" 만으로는 뭐가 달라졌는지 모르신다.

### ⑤ 편집률이 안 내려갔으면 숨기지 않는다

```
고쳐주신 양이 여전히 40% 안팎이에요.

제가 엉뚱한 걸 배우고 있을 수 있어요.
어떤 부분을 주로 고치시는지 한 줄만 말씀해주시면 그쪽을 집중해서 볼게요.
그래도 그대로면 만든 사람이 봐야 할 문제예요 — 「안 된 일 알려주기」 를 눌러주세요.
```

**잘 되고 있다고 말하지 않는다.** 원장님이 프로그램을 믿고 매번 절반을
고치시는 것보다, 안 되고 있다고 아시는 편이 낫다.

## 안 하는 것

- 새 자료를 읽지 않는다 (그건 `/정리`)
- 글을 새로 쓰지 않는다 (그건 `/글쓰기`)
- 표현사전을 **자동으로 확정하지 않는다.** 판정이 바뀌는 것은 여쭙는다
