## 할 일

### 0. 먼저 프로그램 자신을 본다 — 이걸 건너뛰지 않는다

원장님 컴퓨터마다 설정이 다르다. **글은 나오는데 파이프라인이 안 도는 사고가 실제로 있었다** —
지시서 일곱 장 중 다섯 장이 등록조차 안 됐는데 오류가 안 났고, 오케스트레이터가 조용히 혼자
다 써버렸다. 글이 나와서 아무도 몰랐다. 그래서 여기서 매번 확인한다.

```bash
node bin/lib/checker.mjs history >/dev/null && echo "검수기 OK"
ls .claude/agents/*.md | wc -l          # 7 이어야 한다
ls .claude/commands/*.md | wc -l        # 13 이어야 한다
ls .claude/지식층/*.md .claude/지식층/지식팩/*.md 2>/dev/null | wc -l   # 6 이어야 한다
```

그다음 **각 지시서의 맨 앞이 제대로 닫혀 있는지** 본다. `.claude/agents/*.md` 는 모두
1번째 줄이 `---` 이고 **5번째 줄이 다시 `---`** 여야 한다. 닫는 `---` 가 없으면 그 지시서는
**등록되지 않는다.** 오류는 안 난다 — 그래서 눈으로 봐야 한다.

```bash
for f in .claude/agents/*.md; do
  echo "$(basename $f): $(grep -n '^---$' "$f" | sed -n 2p | cut -d: -f1)"
done
```

일곱 줄이 전부 `5` 여야 한다. 다른 숫자가 하나라도 있으면 **원장님께 알리고 멈춘다.**
그 상태로 글을 쓰면 나오기는 하는데 설계대로 안 돈다.

마지막으로 **Task 도구를 쓸 수 있는지** 본다. 파이프라인은 지시서 일곱 장을 차례로 부르는데,
Task 가 막혀 있으면 부를 수가 없다. 이 세션에서 Task 를 쓸 수 있는지 확인하고,
못 쓰면 원장님께 이렇게 말씀드린다:

> 글 쓰는 담당을 나눠 부를 수가 없어요. 화면의 **글 쓰기** 단추로 시작해주시면 제대로 돌아요.

### 1. 그다음 자료를 본다

2. `node bin/lib/checker.mjs cases` — 사례 보유 현황과 다음에 쓸 사례

   - 6개월 넘은 정보
   - 근거 없는 주장 (`[미확인]` 표시된 것)
   - 중복된 사례
4. `10_학원위키/톤가이드.md` 가 있는지 확인. 없으면 만들자고 안내한다

## 보고

원장님께 이렇게 알려드린다.

- **프로그램이 온전한지 한 줄로.** 다 맞으면 "프로그램은 이상 없어요" 한 줄이면 된다.
  숫자가 안 맞으면 무엇이 몇 개인지 말하고, **업데이트 파일을 다시 받으시라고** 안내한다.
  파일 경로를 나열하지 않는다 — 원장님이 고칠 수 있는 것이 아니다
- 쓸 수 있는 새 사례가 몇 건 남았는지. **2건 이하면 먼저 채우시라고 말한다**
- 최근 글들이 같은 사례에 몰려 있지 않은지
- 오래돼서 고쳐야 할 정보가 있는지

블로그가 멈추는 진짜 원인은 글재주가 아니라 쓸 사례가 떨어져서다. 그걸 미리 알린다.
