주제: $ARGUMENTS

## 주제 뒤에 붙어 올 수 있는 것

화면에서 "누구에게 쓸지 고르기"를 쓰시면 주제 뒤에 이런 게 붙어 옵니다.

```
/글쓰기 중2 서술형 감점 — 독자상태=불안형 글유형=설명형 대표자산=성적문제 모드=한번보기
```

붙어 있으면 **그대로 따릅니다.** `topic-scout` 에게 그대로 넘기고, 다시 정하지 않습니다.
없으면 `topic-scout` 이 알아서 정합니다. **원장님이 고르신 걸 뒤집지 않습니다.**

`모드=` 는 topic-scout 에게 넘기지 않습니다. **지휘하는 쪽이 씁니다** —
어디서 멈추고 원장님께 여쭐지를 정하는 값입니다. 아래 "검수 모드" 참조.
안 붙어 있으면 `한번보기` 입니다.

## 시작 전 ⓪ — 프로그램이 온전한가

**이걸 건너뛰면 반쪽짜리 글이 나온다.** 그리고 원장님은 그게 반쪽인 줄 모르신다.

`architect` 와 `writer` 의 지시서에는 "이 파일들을 먼저 읽어라 — 선택이 아니다" 라고
박혀 있다. 그 파일이 없으면 **에이전트는 오류를 내지 않고 그냥 아는 대로 쓴다.**
제목 규칙도, GEO 규칙도, 윤문 규칙도 안 걸린 글이 나온다.

실제로 그렇게 돈 적이 있다 — 압축 파일명이 윈도우에서 깨져 지식층 폴더가 통째로
비어 있었는데, 파이프라인은 1단계를 끝내고 2단계로 넘어가려 했다.

```bash
for f in .claude/지식층/방법론.md .claude/지식층/seo-guide.md \
         .claude/지식층/법규-금칙.md .claude/지식층/윤문-규칙.md \
         .claude/지식층/지식팩/글쓰기기술.md; do
  [ -s "$f" ] || echo "없음: $f"
done
ls .claude/agents/*.md 2>/dev/null | wc -l    # 7 이어야 한다
ls .claude/commands/*.md 2>/dev/null | wc -l  # 13 이어야 한다
```

**하나라도 없거나 개수가 모자라면 글을 쓰지 않는다.** 이렇게 말씀드리고 멈춘다.

```
프로그램 파일이 일부 빠져 있어서 지금 글을 쓰면 반쪽짜리가 나와요.

받으신 압축을 다시 한 번 풀어주시겠어요?
그래도 그러면 새 압축을 다시 받으셔야 해요. 저희 쪽에서 다시 보내드릴게요.
```

**"일단 돌려볼까요?" 라고 묻지 않는다.** 원장님은 무엇이 빠졌는지 판단하실 수 없고,
반쪽짜리 글이 나오면 그게 이 프로그램의 실력인 줄 아신다. 그게 더 나쁘다.

## 시작 전 두 가지 확인

**① 준비가 됐나** — `00_내학원자료/01_기초정보/` 가 비어 있으면 `/시작` 부터 하시라고 안내하고 멈춘다.

**② 지난 글 피드백을 받았나** — `20_완성글/` 의 가장 최근 글에 `편집본.md` 가 없으면 먼저 여쭙는다.

```
지난번 "○○○" 글, 블로그에 올리시면서 고치신 데 있으세요?
고치신 걸 알려주시면 이번 글부터 반영돼요. (/피드백)

없으시면 그냥 진행할게요.
```

**한 번만 묻는다.** 됐다고 하시면 다시 안 묻는다.

### 먼저 — 하다 만 게 있는지 본다

중간에 끊긴 작업이 있으면 **처음부터 다시 하지 않는다.** 이미 만든 것을 쓴다.
한 편에 20~30분이 들고 그게 원장님 돈이다.

```bash
ls -d 20_완성글/*/작업 2>/dev/null | while read d; do
  [ -f "$(dirname "$d")/최종.md" ] || echo "미완성: $d"
done
```

미완성 폴더가 있고 **원장님이 지금 말씀하신 주제와 같으면** 이렇게 여쭙는다.

```
지난번에 "○○○" 쓰다가 중간에 멈췄어요.
초안까지는 나와 있어요. 이어서 할까요, 처음부터 다시 할까요?

  [이어서]  [처음부터]
```

**이어서** 하시면 `작업/` 안에 있는 것부터 확인하고, **없는 단계부터** 시작한다.

| 있는 파일 | 여기서부터 |
|---|---|
| `1_기획.json` 까지 | 3번 (architect) |
| `2_목차.md` 까지 | 4번 또는 5번 |
| `4_초안.md` 까지 | 6번 (검수) |
| `5_윤문.md` 까지 | 6번 (검수) |

읽어 들인 파일은 **다시 만들지 않는다.** `1_기획.json` 의 질문·4축·템플릿·사례를
그대로 이어서 쓴다. 주제가 다르면 새 폴더로 시작한다.

### 작업 폴더를 먼저 정한다

시작할 때 `20_완성글/<날짜>_<주제슬러그>/` 를 만들고, 이 경로를 **모든 서브에이전트 프롬프트에
`WORK_DIR` 로 넘긴다.** 각 에이전트는 결과를 텍스트로 돌려주는 동시에 이 폴더 아래
`작업/` 에 파일로도 남긴다.

#### 슬러그를 짓는 규칙 — 윈도우에서 폴더가 안 만들어진다

원장님이 주신 주제를 그대로 폴더 이름으로 쓰면 안 된다.
**윈도우는 파일 이름에 이 글자들을 못 쓴다:** `\ / : * ? " < > |`
"중2 서술형: 답은 맞는데?" 같은 주제에는 `:` 와 `?` 가 둘 다 들어 있다.
맥에서는 만들어지고 윈도우에서는 **글쓰기가 통째로 실패한다.** 원장님은 이유를 모르신다.

| 규칙 | |
|---|---|
| 못 쓰는 글자 | `\ / : * ? " < > |` 와 제어문자 — **전부 뺀다** (바꾸지 말고 뺀다) |
| 공백 | `_` 로 바꾼다 |
| 마침표·공백으로 끝나면 | 잘라낸다. 윈도우가 이름 끝의 `.` 과 ` ` 를 조용히 지운다 |
| 길이 | **한글 20자 이내.** 윈도우 전체 경로 한도가 260자라 여유가 없다 |
| 비면 | `글` 로 한다. 빈 이름은 폴더를 못 만든다 |

```
"중2 서술형: 답은 맞는데?"  →  2026-08-26_중2_서술형_답은_맞는데
"초6 겨울방학 <선행>"        →  2026-08-26_초6_겨울방학_선행
```

**슬러그는 사람이 알아보기만 하면 된다.** 제목은 `최종.md` 안에 따로 있으니
여기서 정확할 이유가 없다. 짧고 안전한 쪽을 고른다.

### 지휘 (conductor) — 이게 규율이다

원장님 지적에서 나온 규칙이다.

> "어느 정도까지만 하고 다음으로 넘기기 위한 조건과 기준이 있어야 하지 않나?
> 어떤 단계에서 막히는 순간 후반 에이전트가 전부 무한대기만 하는 상황이 발생한다."

**단계마다 세 가지를 본다. 셋 다 통과해야 다음으로 넘어간다.**

| | 무엇 | 어떻게 |
|---|---|---|
| ① 나왔나 | 산출물 파일이 있고 비어 있지 않은가 | `test -s` |
| ② 쓸 만한가 | 지어낸 사례·깨진 JSON·짧은 본문이 아닌가 | `node bin/lib/stage.mjs` |
| ③ 시간 안에 왔나 | 그 단계 상한을 넘지 않았는가 | `date +%s` 로 잰다 |

#### 시작할 때 시각을 적어둔다

```bash
T0=$(date +%s)
```

각 단계가 끝날 때마다 `date +%s` 로 다시 재서 걸린 시간을 계산한다.

#### 검수 모드 — 어디까지 원장님 확인 없이 갈지

주제 뒤에 `모드=` 로 붙어 온다. **안 붙어 있으면 `한번보기`** 다.
화면에서 원장님이 고르신 값이 그대로 실려 온다.

```
/글쓰기 중2 서술형 감점 — 모드=꼼꼼히
```

| 모드 | 멈추는 곳 | 첫 결과까지 |
|---|---|---|
| `한번보기` **(기본)** | ① 주제 확정 뒤 | **1분 30초** |
| `맡기기` | 안 멈춘다 | 20분 |
| `꼼꼼히` | ① 주제 · ② 목차 뒤 | 1분 30초 |

> **기본값이 왜 `한번보기` 인가.** 주제가 어긋난 채로 20분을 태우면 그 돈이 통째로 날아간다.
> ①에서 멈추면 **1분 30초**에 아신다. 원장님은 화면에서 모드를 바꾸실 수 있고,
> 고르신 값이 `모드=` 로 실려 온다.


**총 시간은 안 줄어든다.** 줄어드는 건 **틀린 채로 도는 시간**이다. 주제가 어긋났을 때
지금은 20분을 다 태우고 나서 안다. ①에서 멈추면 1분 30초에 안다.

**모드가 무엇이든 지휘 세 검사는 그대로 돈다.** 모드는 *원장님께 여쭐지*를 정하는 것이지
*검사를 건너뛸지*를 정하는 것이 아니다.

##### 멈출 때는 이렇게 여쭙는다

원장님이 **30초 안에 판단**하실 수 있어야 한다. 파일 이름·경로·JSON 을 보여드리지 않는다.

① 주제 뒤:

```
쓸 주제를 이렇게 잡았어요.

  질문      예비중, 중학 문법을 미리 해야 하는지 고민될 때
  글 종류    설명형 — 판단 기준을 세워드리는 글이에요
  근거       '서술형 풀이과정' · '예비중 상담' 두 사례를 써요
  읽는 분    예비중 학부모, 아직 알아보시는 중

이대로 갈까요? 바꾸고 싶은 데가 있으면 말씀해주세요.
```

② 목차 뒤 — **제목만** 나열한다. 각 줄이 어느 사례에 묶였는지 한 칸에 적는다.

```
글 순서를 이렇게 잡았어요.

  1. 지금 시작해도 늦지 않은 이유       ← 예비중 상담
  2. 미리 하면 뭐가 달라지나요?         ← 서술형 풀이과정
  3. 이런 경우엔 서두르지 않아도 돼요   ← 예비중 상담
  4. 상담 오시기 전에 준비하실 것       ← 근거 없이 씀

이 순서로 쓸까요?
```

##### 멈춘 다음

**그 자리에서 끝낸다.** 되묻지 않고, 답을 기다리지도 않는다 —
파이프라인은 헤드리스로 돌아서 도중에 답을 받을 통로가 없다.
`작업/` 을 그대로 남기고 종료하면 **"하다 만 게 있는지 본다"가 다음 실행에서 받는다.**

원장님께는 마지막에 이 한 줄을 덧붙인다.

```
괜찮으시면 글 쓰기를 다시 눌러주세요. 여기서부터 이어서 해요.
```

고치실 데를 말씀하시면 **그 단계만 다시 돌린다.** 처음부터 다시 하지 않는다.

#### 단계별 상한 — **막힌 걸 잡는 선이지, 느린 걸 벌주는 선이 아니다**

| 단계 | 담당 | 상한 | 실측 |
|---|---|---|---|
| 1 | `topic-scout` | 3분 | 84초 |
| 2 | `architect` | 8분 | 227초 |
| 3 | `researcher` | 15분 | 248초 · **595초**(웹 32회) |
| 4 | `writer` | 9분 | 256초 |
| 5 | `polisher` | 5분 | 279초는 폭주였다. 정상으로 끝난 회차는 113초 |
| — | 검수·조립 | 4분 | 124초 |
| | **전체** | **49분** | |

**상한을 넘겼을 때 무엇을 볼지가 핵심이다. 시간이 아니라 산출물을 본다.**

| 산출물 | 상한 | 어떻게 |
|---|---|---|
| 나왔고 판정 통과 | 넘김 | **그냥 간다.** 한 줄로 알리기만 한다 |
| 안 나왔거나 판정 실패 | 넘김 | **멈춘다.** 막힌 것이다 |

멀쩡한 결과를 55초 넘겼다고 멈춰 세우면 원장님만 손해다. 다시 부르면 그 돈이 또 나간다.
**상한의 쓸모는 "이 단계가 막혔나"를 아는 것이지 "느렸나"를 따지는 게 아니다.**

넘겼는데 결과가 멀쩡하면 이렇게만 말씀드리고 넘어간다.

```
3단계가 9분 55초 걸렸어요 (보통 4~10분). 결과는 멀쩡해서 그대로 갈게요.
```

> 왜 조사만 상한이 두 배인가. 실측이 248초와 595초로 두 배 넘게 벌어졌다.
> 사례로 다 덮이면 통째로 건너뛰고, 제도·통계를 처음 찾는 글은 웹을 서른 번 넘게 뒤진다.
> **같은 단계가 아니라 아예 다른 일이다.** 한 번 찾은 것은 `작업/3_조사.md` 에 남아
> 다음 글에서 다시 안 찾는다.

**끊을 수는 없다.** 도는 중인 서브에이전트를 중간에 멈추는 방법은 없다.
할 수 있는 건 **다음 단계를 시작하지 않는 것**이다.

#### 판정 — AI 가 하지 않는다

```bash
node bin/lib/stage.mjs "20_완성글/<WORK_DIR>/작업" . <단계번호>
```

정규식과 JSON 파싱만 쓴다. 나가면 `0`, 걸리면 `1` 이다.
**나온 지적을 네 판단으로 덮지 않는다.** 판정기가 "없는 사례를 가리킨다"고 하면
그건 지어낸 것이다. 넘어가지 않는다.

#### 다음에 누구를 부를지는 **당신이 정하지 않는다**

```bash
node bin/lib/dispatch.mjs 다음 20_완성글 <검수JSON> <문장수>
```

이것이 `{"다음":"수리","담당":"polisher",...}` 처럼 답한다. **그대로 따른다.**

> **2026-08-26 사고.** 이 파일에 "반려면 writer 에게 넘긴다" 고 **이미 적혀 있었는데**
> 지휘가 polisher 를 불렀다. 합쇼체 59.6%짜리 초안을 짚어 고치라고 시킨 것이라
> 이길 수 없는 일이었다. 두 번 시도해 두 번 다 걸렸고 **11분과 587만 토큰이 버려졌다.**
>
> 그래서 이제 **문지기가 실행 전에 막는다.** 허가되지 않은 담당은 부르려 해도 안 뜬다.
> 억지로 부르지 말고 `dispatch.mjs` 가 정한 대로 가라. 그게 빠른 길이다.

| 답 | 무엇을 한다 |
|---|---|
| `통과` | 9번으로 간다 |
| `수리` | `polisher` 를 부른다. **`수리대상` 을 그대로 프롬프트에 넣는다** |
| `재작성` | `writer` 를 부른다. **`재작성사유` 를 넣는다** |
| `멈춤` | 멈추고 원장님께 말씀드린다. 더 부르지 않는다 |

담당이 끝날 때마다:

```bash
node bin/lib/dispatch.mjs 끝냄 20_완성글 <담당이름>
```

`_진행.json` 을 직접 고치려 하지 마라. **문지기가 막는다.**

#### 멈출 때 원장님께

```
○단계에서 막혔어요. 한 번 더 해봤는데도 같은 데서 걸려요.

  걸린 것: (판정기가 짚은 걸 쉬운 말로 한 줄)

지금까지 한 건 그대로 남아 있어요.
잠시 뒤에 글 쓰기를 다시 눌러주시면 이어서 해볼게요.
```

**조용히 넘어가지 않는다.** 근거 없는 글이 나오는 것보다 안 나오는 게 낫다.

#### 앞이 비면 뒤를 시작하지 않는다

3단계(`researcher`)는 건너뛸 수 있다. 그것 말고는 **앞 산출물 없이 다음을 부르지 않는다.**
지시서 다섯 장이 등록조차 안 됐는데 글은 나온 적이 있다 — 오케스트레이터가 조용히
혼자 다 써서 아무도 몰랐다. 파일을 보는 이유가 이것이다.

```bash
test -s "20_완성글/<WORK_DIR>/작업/4_초안.md" || { echo "앞 단계가 비었다 — 멈춘다"; }
```

### 순서

**단계 2~5는 부른 뒤 반드시 지휘 세 검사를 돌린다.** 아래에서는 "→ 지휘" 로 줄여 쓴다.

1. `T0=$(date +%s)` · **`node bin/lib/dispatch.mjs 시작 20_완성글`** 을 반드시 먼저 돌린다.
   이걸 안 돌리면 **문지기가 담당을 하나도 안 띄운다.** 그다음
   `node bin/lib/checker.mjs cases` 와 `node bin/lib/checker.mjs history` 를 읽는다
2. `node bin/lib/dispatch.mjs 다음 20_완성글 topic-scout` → `topic-scout` 호출 → `작업/1_기획.json` → 지휘(`stage.mjs ... 1`, 상한 3분) → 질문 1개와 4축 확정
   · **`맡기기` 가 아니면 여기서 주제를 보여드리고 멈춘다**
3. `dispatch.mjs 끝냄 20_완성글 topic-scout` → `dispatch.mjs 다음 20_완성글 architect` → `architect` 호출 → `작업/2_목차.md` → 지휘(`... 2`, 상한 8분)
   · **`꼼꼼히` 면 여기서 목차를 보여드리고 멈춘다**
4. `끝냄 architect` → 목차에 `없음` 항목이 있을 때만 `다음 researcher` → `researcher` 호출 → `작업/3_조사.md` → 지휘(`... 3`, 상한 15분)
5. `끝냄`(돌린 담당) → `다음 20_완성글 초안` → `writer` 호출 → `작업/4_초안.md` → 지휘(`... 4`, 상한 9분)
6. `node bin/lib/checker.mjs check <초안> --json > 작업/_검수.json` 으로 지적을 받는다
7. `node bin/lib/dispatch.mjs 다음 20_완성글 작업/_검수.json <문장수>` 로 **갈림길을 받는다**
   · `수리` → `polisher` 에게 **초안 본문과 `수리대상` 을 프롬프트로** 준다.
     돌아온 JSON 을 `node bin/lib/checker.mjs 수리 <초안> <작업폴더>` 에 넘기면
     Node 가 적용해 `작업/5_윤문.md` 를 만든다. 그다음 6번으로 한 번 더
   · `재작성` → `writer` 에게 `재작성사유` 를 주고 4번부터 다시. **한 편에 한 번뿐**
   · `멈춤` → 멈춘다
8. 지휘 세 검사(`stage.mjs ... 5`)를 돌린다
9. 통과하면 같은 폴더에 저장:
   - `최종.md` — 제목 후보 3개 + 본문 + CTA + 해시태그 + **발행 전 확인** (아래)
   - `최종.html` — 네이버 에디터 붙여넣기용
   - `검수리포트.md` — 검수기 출력 그대로

   `최종.md` 맨 아래 "이 글은 이렇게 썼습니다" 메모 안에 **이 네 줄을 반드시 넣는다.**
   법으로 막힌 표현을 프로그램이 전부 막지는 않는다 — 마지막으로 보시는 분은 원장님이다.

   ```
   ### 올리시기 전에 한 번만 봐주세요

   - **사진 자리** `[사진 자리 ①]` 표시에 직접 찍으신 사진을 넣어주세요
   - **학생 이름과 얼굴**은 가려주세요. 사례에 나온 이름은 이미 바꿔 썼어요
   - **성적이 오른다는 약속**으로 읽힐 문장이 없는지 봐주세요
   - 이 메모는 **원장님만 보시는 것**이라 빼고 올리시면 돼요
   ```
10. **`node bin/lib/dispatch.mjs 끝 20_완성글`** — 글쓰기가 끝났다고 표시한다.
    이걸 안 하면 다음에 `/피드백` 같은 다른 명령이 담당을 부를 때 문지기가 막는다
11. `node bin/lib/checker.mjs record` 로 발행 대장에 기록한다. `--template` 은 네 가지 중 하나여야 하고, `--cohort`(학생군) `--reader`(독자상태) `--asset`(대표자산)도 함께 넘긴다. 안 넘기면 `C1`·`C2`·`/제안`이 셀 수가 없다

```
   최종.md 를 열어서 본문을 복사해 붙여넣으시면 돼요.
   글 안에 [사진 자리 ①: ...] 표시가 2개 있어요. 거기에 직접 찍으신 사진을 넣어주세요.

💬 올리시고 나서

```

3회차에도 통과 못 했으면 **무엇이 왜 걸렸는지**를 솔직히 말하고, 원장님이 직접 고치실 수 있게 위치를 짚어드립니다.
