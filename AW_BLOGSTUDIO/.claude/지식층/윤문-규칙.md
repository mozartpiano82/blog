# 한국어 윤문 규칙 — 윤문기(⑤) 사양

> **핵심 전제.** AI 티는 문체 취향의 문제가 아니라 **구조적 문제**다.
> LLM은 영어로 생각하고 한국어로 번역해 내보낸다. 그래서 나오는 것이 **번역투**다.
> 고칠 대상은 "어색함"이 아니라 **영어 문장 구조의 잔재**다.

---

## 0. 왜 번역서 3권이 근거인가

`im-not-ai`가 잡아내는 70패턴과, 번역가들이 40년간 싸워온 번역투는 **같은 것**이다.
LLM이 새로 만든 문제가 아니라, **기존 번역투 문제를 증폭시킨 것**이다.

이희재는 이걸 한 문장으로 정리한다.

> **"군살 없는 글이 좋은 글입니다. 불필요한 쉼표는 글을 지저분하게 만듭니다."**

## 1. 심각도 체계 (im-not-ai 계승)

| 등급 | 판정 | 처리 |
|---|---|---|
| **S1** | 결정적. 한 번만 나와도 AI로 확신 | **무조건 제거** |
| **S2** | 강함. 1~2회는 허용 | **3회 이상이면 제거** |
| **S3** | 약함. 단독으로는 문제 아님 | **다른 패턴과 겹칠 때만** |

**변경률 상한** — 원문 보존이 우선이다.
- 30% 초과 → 경고, 근거를 리포트에 남긴다
- 50% 초과 → **중단하고 원문 보존.** 과교정은 다른 글을 만든다

## 2. 쉼표 — S1

『번역의 모험』 1장 전체가 이 주제다. **한국어에서 쉼표가 부쩍 늘어난 것은 영어 탓이다.**

### 2-1. 접속부사 뒤 쉼표 (S1)

> "하지만, 따라서, 더욱이, 다음에는 무조건 쉼표를 찍는 사람이 적지 않습니다.
> **영어에서 however, therefore, moreover 다음에는 쉼표를 찍으니까 그냥 따라서 찍는 거겠지요.**"

```
✗ 하지만, 성적은 결과로 따라옵니다.
✓ 하지만 성적은 결과로 따라옵니다.
```

**정규식**: `^(하지만|그러나|따라서|그래서|또한|더욱이|물론|즉|예를 들어)\s*,`
→ 쉼표 제거

### 2-2. 종속절 뒤 쉼표 (S1)

> "긴 문장이 아닌데도 별 생각 없이 글 안에 쉼표를 찍는 사람이 많습니다.
> **역시 영어의 영향 탓으로 보입니다.**"

영어는 `Although ~, ~` 구조에서 종속절 끝을 표시할 방법이 쉼표뿐이다.
**한국어는 어미(`-면` `-지만` `-고` `-며`)가 그 일을 이미 한다.** 쉼표가 겹친다.

```
✗ 그 여자가 자기소개를 안 했으면, 통 못 알아볼 뻔했다.
✓ 그 여자가 자기소개를 안 했으면 통 못 알아볼 뻔했다.
```

**정규식**: `(면|지만|는데|아서|어서|면서|니까|라서|다가|고|며)\s*,`
→ 앞뒤 절 합쳐 40자 미만이면 쉼표 제거. 40자 이상이면 유지 검토

> ⚠️ **긴 문장에서는 쉼표가 정당하다.** 무조건 지우면 가독성이 죽는다.
> 길이 조건을 반드시 건다.

### 2-3. 밀도 상한 (S2)

**실측 기준선** — 한국인 학원장 실측 글 3편:

| 지표 | 사람(실측) | 상한 |
|---|---|---|
| 문장당 쉼표 | **0.33개** | 0.5개 |
| 어미 뒤 쉼표 (문장당) | 11.1% | — |

> **규칙 P-C1.** 생성 글의 문장당 쉼표가 **0.5개를 넘으면** 2-1·2-2를 강제 적용한다.

## 3. 대명사 — S1

LLM이 만든 한국어는 대명사 밀도가 **번역하지 않은 한국어의 2~3배**다.
한국어는 주어를 생략하는 언어인데, 영어 구조가 주어를 강제로 채운다.

```
✗ 그는 그의 시계를 보았다.
✓ 시계를 보았다.

✗ 그 아이는 그의 숙제를 가져왔습니다.
✓ 아이가 숙제를 가져왔습니다.
```

**처리**: `그|그녀|그것|그들|그의|그녀의` 검출 → **절반~70%를 삭제 후보**로 본다.
주어 생략 또는 명사 재사용으로 재구성한다.

**보너스 — 명사로 되돌리면 리듬도 산다.** 『번역의 모험』 5장:

> "대명사 '그'를 명사 '시장'으로 되돌리면 균형감이 더 살아나겠지요."
> ```
> 1. 시장의 약점은 과장되었고 그 강점은 과소평가되었다.
> 3. 시장의 약점은 과대평가되었고 시장의 강점은 과소평가되었다.  ← 낫다
> ```

## 4. 피동·이중피동 — S1

```
✗ 판단되어진다  → ✓ 판단한다
✗ 발생되어진다  → ✓ 발생한다
✗ 보여집니다    → ✓ 보입니다
✗ 생각되어집니다 → ✓ 생각합니다
```

**정규식**: `(되어지|어지는|여지는|되어집|보여지|불려지|쓰여지)` → S1 즉시 교정

**단순 피동도 능동으로** (S2):
```
✗ 감점이 되는 경우가 많습니다  → ✓ 감점을 많이 받습니다
```

## 5. 번역투 구문 — S1/S2

| 패턴 | 등급 | 고침 |
|---|---|---|
| `~에 대해/대한` 남발 | S2 | 조사로 바꾼다. "수학에 대해 이야기" → "수학 이야기" |
| `~를 통해` | S2 | "데이터 분석을 통해 얻는다" → "데이터를 분석해 얻는다" |
| `~에 있어서` | S1 | 일본어투. "학습에 있어서" → "학습에서" |
| `~라는 점에서` | S2 | 축약 |
| `~할 필요가 있다` | S1 | "논의할 필요가 있다" → "논의해야 한다" |
| `~할 것이다` (추측) | S2 | "도움이 될 것입니다" → "도움이 됩니다" |
| `~을 갖고 있다` | S1 | 일본어투. "의미를 갖고 있다" → "의미가 있다" |
| `~임에 틀림없다` | S1 | 일본어투 (『번역투의 유혹』 지적) |
| `~적(的)` 남발 | S2 | "본질적인 문제" → "본질 문제" / "근본 문제" |
| `강한 ~를 가지고 있다` | S1 | "강한 경쟁력을 가지고 있다" → "경쟁력이 강하다" |

## 6. 상투구 — S1

AI가 문단을 닫을 때 쓰는 관용구. **한 번만 나와도 티가 난다.**

```
결론적으로 / 본질적으로 / 궁극적으로
시사하는 바가 크다 / ~라고 볼 수 있다
중요한 것은 ~라는 점이다
~에 다름 아니다
새로운 지평을 열다 / 화두를 던지다
```

**예**
```
✗ 결론적으로 AI 규제에 대해서 논의할 필요가 있다는 점은 시사하는 바가 크다.
✓ 결국 AI 규제를 논의해야 한다.
```

> **문법적으로는 다 멀쩡하다. 그런데 한국어 쓰는 사람은 보통 이렇게 안 쓴다.**
> "완벽한데 사람 같지 않다"가 곧 AI 티다.

## 7. 리듬 — S1 (가장 중요)

**AI 글의 최대 특징은 문장 길이가 균일하다는 것이다.**

『번역의 모험』 5장은 이걸 '맞추기(운율)'로 다룬다.

> "운율은 시 같은 운문에서만 중요한 것이 아닙니다.
> **평범한 산문에서도 운율을 살린 문장은 독자를 편하게 해줍니다.**"

주의: 이희재가 말하는 '맞추기'는 **동급 요소의 형태 통일**이지 문장 길이 균일화가 아니다.
둘을 헷갈리면 안 된다.

| | 좋은 맞추기 | 나쁜 균일함 |
|---|---|---|
| 대상 | 나열되는 동급 요소 | 문장 전체 길이 |
| 예 | "부자와 빈자" (한자어끼리) | 모든 문장이 35자 |
| 효과 | 박자감 ↑ | **AI 티** |

### 7-1. 문장 길이 분산 (S1)

**실측 기준선** — 기준 학원장 글:

| 지표 | 사람(실측) | AI 위험선 |
|---|---|---|
| 평균 | 29.9자 | — |
| **표준편차** | **16.2** | **14 미만이면 위험** |
| 변동계수 | 0.54 | 0.45 미만이면 위험 |
| 30~50자 집중도 | 32.4% | **45% 초과면 위험** |

> **규칙 P-R1.** 표준편차 14 미만 → **반려.** 짧은 문장을 섞어 분산을 복원한다.
> **규칙 P-R2.** 30~50자 집중도 45% 초과 → 경고.

### 7-2. 종결어미 다양성 (S2)

같은 어미가 **연속 3문장** 이상 반복되면 기계적으로 읽힌다.

> **규칙 P-R3.** 동일 종결어미 3연속 → 교정.
> **규칙 P-R4.** 합쇼체(`~습니다`) 비율이 톤가이드 목표치를 넘으면 교정.
> (기준 학원장은 3.1%. AI 기본값은 합쇼체라 그냥 두면 남의 글이 된다.)

### 7-3. 동급 요소 형태 통일 (S3 — 개선 항목)

```
✗ 채권 매매, 칼 갈기, 유리 닦기, 펌프 설치하기
✓ 채권 사고팔기, 칼 갈기, 유리 닦기, 펌프 설치하기   ← '-기'로 통일
```

**고유어는 고유어끼리, 한자어는 한자어끼리** 모으면 박자감이 산다.
```
△ 생김새와 억양     (고유어 + 한자어)
○ 생김새와 말씨 / 외모와 억양
```

## 9. 처리 경로 (im-not-ai 3-route 계승)

| 경로 | 조건 | LLM 호출 |
|---|---|---|
| **Light** | 결정론 검사에서 S1 0건, S2 2건 이하 | 1회 (또는 조기 종료) |
| **Standard** | 일반적인 AI 초안 | 2회 — 진단 → 표시 구간만 재작성 |
| **Heavy** | S1 5건 이상 또는 장문 | 3회 — 진단 → 재작성 → 마무리 |

> **핵심.** 결정론 코드가 **먼저 찾고**, LLM에는 **표시된 구간만** 다시 쓰게 한다.
> 전체를 다시 쓰게 하면 원문이 사라지고 새로운 AI 글이 나온다.

## 10. 4대 원칙 (im-not-ai)

1. **의미 보존** — 사실·주장·숫자·고유명사는 그대로
2. **근거 기반** — 패턴이 표시된 구간만 고친다
3. **장르 일관** — 톤과 격식을 유지한다
4. **과교정 금지** — 30% 경고 / 50% 중단

## 11. 구현 사양 (M3)

```
[결정론 검사기 — TypeScript]
  입력: 초안 텍스트 + 톤가이드(목표치)
  출력: { 패턴ID, 위치, 심각도, 제안 }[]

  S1 정규식군   쉼표(접속부사/종속절) · 대명사 · 이중피동 ·
                번역투 구문 · 상투구 · 이모지
  S1 통계군     문장길이 표준편차 · 30~50자 집중도
  S2 통계군     쉼표 밀도 · 종결어미 연속 · 합쇼체 비율
  S3            동급요소 형태 · 고유어/한자어 혼용

[LLM 재작성]
  표시 구간만 전달. 전체 재작성 금지.

[리포트]
  04_검수리포트.md — 패턴별 검출 수, 변경률, 미적용 사유
```

(학원장에게 파이썬 설치를 요구할 수 없다).
